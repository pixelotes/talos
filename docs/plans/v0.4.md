# v0.4 "Serves": implementation record

What was built for the server milestone of [ROADMAP.md](../ROADMAP.md), done
right after v0.1 as the roadmap allows ("can move earlier"). The contract is
[API.md](../API.md) §2; the HTTP stack is
[ADR 0017](../adr/0017-http-stack.md) (accepted).

| Roadmap scope | Status |

## What was done

- **Shape.** The `talos` crate gained a library target: `clock.rs` (the
  clock read before each turn; `LocalClock` caches the UTC offset for a
  minute), `wire.rs` (the `talos` object, used by `ask --json` and the
  server) and `server/` behind the `server` feature (on by default, no
  dependency). `main.rs` parses `serve [--bind ADDR] [--port N] [--token
  TOKEN]` (or `TALOS_TOKEN`); `--lang` and `--seed` apply as for the other
  commands. Every turn goes through `Engine::respond`, as `ask` and `chat`.
- **Endpoints and errors** as API.md §2 now specifies them in full:
  OpenAI-shaped error bodies for malformed HTTP or JSON, a missing user
  message, wrong types, unknown routes (404), wrong methods (405 with
  `Allow`), oversized bodies (413), slow requests (408), too many
  connections (503). Unknown fields are ignored.
- **Streaming**: role chunk, one content chunk with the whole reply, a
  finish chunk carrying the `talos` object, the usage chunk when asked,
  `data: [DONE]`; sent with a `Content-Length`.
- **Conversation identity.** Key (`metadata.conversation` or
  `X-Talos-Conversation`), then `user`, then a 128-bit FNV-1a fingerprint of
  the user and assistant messages before the last user message. The dialog
  state is the engine's own bounded store (1 024 conversations, 30 minutes
  idle); the server keeps only a table from fingerprints to conversations,
  with the same bounds. Earlier messages are never replayed.
- **Engine change.** The engine's store evicted the least recently *seen*
  conversation by the turn's clock, ties broken by id; within one second
  (and with a fixed clock, in tests) that was not least recently used. Ties
  are now broken by order of use (`talos-core/src/state.rs`, DESIGN.md §7).
  No golden output changed.
- **Determinism.** Tests start servers in-process with a fixed clock and
  `stopwatch = false`; the same request sequence against two fresh servers
  gives byte-identical bodies (`the_same_requests_give_the_same_bytes`).
  The CLI is unchanged: it always reads the system clock.
- **Tests**: 20 end-to-end tests in `crates/talos/tests/server.rs` over real
  sockets (non-streaming, streaming, each identity mechanism over several
  turns, auth required and refused, the binary refusing an open bind, error
  cases, eviction of the dialog state and of the fingerprint table, two
  concurrent clients, a slow and an idle client not blocking a third, the
  connection cap, keep-alive and close, `100-continue`, chunked bodies, an
  SDK-shaped request); unit tests for the HTTP parser and the identity
  table.

## Exit criteria

| Criterion | Result |
|---|---|
| An off-the-shelf OpenAI client holds a multi-turn exchange, including an open question, with no Talos-specific configuration | **open.** The fingerprint path is tested with requests shaped as such clients send them, but no real client was run, and open questions do not exist before v0.2 |
| Tomos runs its modes against the new server and falls through on `Deflected` and `Unhandled` | **open**, work in Tomos. The server side is ready: `X-Talos-Status` and the `talos` object |
| Server overhead ≤ 1 ms per request | yes: p50 64 µs, p99 122–152 µs (DEVELOPMENT.md, "Server") |
| Memory with the server feature ≤ 12 MB at rest without packs | yes: 5.5–6.3 MB at rest, 9.0–9.4 MB after 11 000 mixed requests |

Also kept: the binary without the server feature is 1 400 864 B (6 MB
budget), with it 1 468 192 B (15 MB budget); measured on macOS, not on the
Raspberry Pi the budgets name.

## Open

- **Real clients.** Run at least two unmodified clients (an OpenAI SDK and a
  chat UI) against `talos serve`, multi-turn, streaming and not, and record
  what they send. This is also the validation DESIGN.md §13.3 asks of the
  fingerprint scheme.
- **Open questions** (v0.2): `pending` is always `false` until then, and the
  "including an open question" criterion waits for it.
- **Retries and regeneration** continue the same conversation, whose state
  has already advanced (API.md §2.3). Harmless today; with open questions it
  may need a rule (for example, keep the state before each turn under the
  prefix fingerprint).
- **Configuration**: limits, the token, the bounds of the store and the bind
  address come from flags, the environment or compiled-in defaults until
  `talos.toml` exists.
- **ADR 0017** awaits the owner's review.
- **Measurements on the target hardware** (Raspberry Pi) and in CI; the CI
  size job still builds the default binary, which now includes the server.
- `cargo deny` was not run (not installed); the server adds no crate.
