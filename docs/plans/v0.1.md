# M1 — v0.1 "A skeleton that talks": implementation plan

The working plan for the first implementation milestone in
[ROADMAP.md](../ROADMAP.md). It is organised in **slices**: each slice ends in
something that runs, and the first one is deliberately the smallest thing that
can answer a greeting.

Implementation works from [docs/spec/](../spec/README.md), chiefly `basics.md`,
`conversation.md` and `reflector.md`.

## Scope reminder

In: the pipeline end to end with **rules only**, manifests, rendering, the
reflector, three CLI commands, seven skills, golden transcripts.

Out, on purpose: the classifier, typed slot filling and open questions (v0.2);
the knowledge store (v0.3); the server (v0.4). In v0.1 a request whose rule
does not capture everything it needs is answered with a short usage hint and
is `unhandled`; Talos does not ask back yet.

## Slices

```
A  hola ──▶ B  pipeline complete ──┬─▶ C  skills (parallel) ──┬─▶ E  measure and close
                                   └─▶ D  reflector ──────────┘
```

### Slice A — "hola" (walking skeleton)

The thinnest vertical cut through every stage. One skill, one intent.

| # | Task | Where |
|---|---|---|
| A1 | Core types: `Lang`, `Turn`, `Outcome`, `Status`, error type | `talos-core` |
| A2 | Normalisation: NFKC, case folding, whitespace, typographic variants; original text kept | `talos-core` |
| A3 | Language: caller hint, then unambiguous words, then default (steps 1, 2, 4 of [ADR 0015](../adr/0015-language-detection.md); the classifier step waits for v0.2) | `talos-core` |
| A4 | Manifest: TOML model and loader for skill, intents, patterns, replies; embedded at build time | `talos-core`, `skills/` |
| A5 | Rule stage: patterns compiled once per language, explicit priority | `talos-core` |
| A6 | `Skill` trait, registry, dispatch; `SkillResult` with `Answer`, `Decline`, `Fail` | `talos-core` |
| A7 | Rendering: `{name}` templates, deterministic variant choice | `talos-core` |
| A8 | Fallback stub: a fixed honest `unhandled` reply per language | `talos-core` |
| A9 | `smalltalk` skill with `smalltalk.greet` only | `talos-skills`, `skills/smalltalk/` |
| A10 | `talos ask "<text>"` and `talos chat`, with `--lang`; exit status by outcome | `talos` |

**Done when**

```
$ talos ask "hola"
¡Hola!
$ talos ask "hello"
Hello!
$ talos ask "escríbeme un poema"; echo $?
No sé hacer eso.
3
```

and the three cases are golden tests. **This is the point at which Talos says
hello back.**

### Slice B — the pipeline, complete

| # | Task |
|---|---|
| B1 | Trace: every stage records its decision; `talos explain "<text>"` prints it |
| B2 | Injected clock and injected random source, so every turn is replayable |
| B3 | Per-conversation state holder (language stickiness with hysteresis, turn counter, recent topic) |
| B4 | Manifest validator and `talos skills check`: schema, both languages present, patterns compile, reply ids used by handlers exist, no two equal-priority rules matching the same example |
| B5 | Golden-transcript harness: a text format for exchanges (`Given:` clock and seed, user turn, expected reply and outcome line), runner, byte-for-byte comparison |
| B6 | Capture extractors the v0.1 skills need: number (both decimal conventions), simple dates and weekdays, option lists |
| B7 | `--json` output of the full outcome on `ask` |

**Done when** a golden file can express any single-turn example from
`basics.md`, and `talos explain` shows which rule fired and why.

### Slice C — the skills (parallel, one owner each)

| # | Skill | Notes |
|---|---|---|
| C1 | `smalltalk` (rest: bye, thanks, how_are_you) | finishes A9 |
| C2 | `identity` | no creator named; not a language model |
| C3 | `help` | `help.capabilities` generated from installed manifests' summaries |
| C4 | `clock` | now, date, weekday, until; per-language conventions |
| C5 | `calc` | own expression parser, exact arithmetic; percent; unit conversion tables |
| C6 | `random` | dice, coin, pick, number; draws only from the injected source |
| C7 | `fortune` | bundled sayings in both languages, the project's own text |

Each skill is a manifest in `skills/<id>/`, a handler module in
`talos-skills`, and a golden file transcribed from its section of `basics.md`.
Skills touch disjoint files; the one shared line each (registration) is added
by whoever integrates.

**Done when** every example in `basics.md` that a rule can reach passes as a
golden test, in both languages, and `talos skills check` is clean.

### Slice D — the reflector (parallel with C)

| # | Task |
|---|---|
| D1 | Script format (data, one file per language) and loader |
| D2 | Engine: shape matching in rank order, capture, reassembly, deterministic variants, no immediate repeats |
| D3 | Reflection: person and pronoun tables per language; the guard list of cases where reflection is skipped for a neutral reply |
| D0 | The safety check for distress, as its own pipeline stage ahead of the reflector and of any open question; numbers from configuration |
| D4 | The `unhandled` boundary: factual-looking questions, generative requests, noise, other languages, long text |
| D5 | First scripts, Spanish and English, written natively: a first tranche of the shapes in `reflector.md` (the rest is the v0.5 coverage pass) |
| D6 | Forbidden-reply check: the anti-examples in `reflector.md` as a test that no script can produce them |

**Done when** the reflector replaces the A8 stub, statuses follow
`reflector.md`, and the stand-alone conversation battery runs end to end and
reports a catch-all rate (a baseline number, not yet a gate).

### Slice E — measure and close

| # | Task |
|---|---|
| E1 | Determinism test: the full golden suite run twice, outputs byte-identical |
| E2 | `talos eval` minimal: run the intent batteries with rules only and report accuracy per language (a baseline for v0.2, not a gate) |
| E3 | Measure on the development machine: resident memory at rest, rule-matched turn p50/p99, cold start, stripped binary size; record them in the repository |
| E4 | Dependency review against the licence and weight policy; `cargo deny` clean |
| E5 | Revisit [ADR 0003](../adr/0003-rust.md) with the real cost of iteration, as that record requires |

**Exit criteria** are the roadmap's: a stranger can hold a short conversation
in either language; identical input and state give byte-identical output;
`talos explain` shows every stage; memory at rest ≤ 8 MB; rule-matched turn
p99 ≤ 2 ms; binary ≤ 6 MB without the server feature.

## Status (2026-11-25)

Slices A–D are done. Slice E: E1 (determinism test), E2 (`talos eval`), E3
(measurements, docs/DEVELOPMENT.md "Footprint") and E5 (ADR 0003 reviewed;
Rust kept, confirmed by the owner) are done; 216 tests pass and `talos skills check`
is clean.

Exit criteria:

| Criterion | Result |
|---|---|
| A short conversation in either language | yes, at a terminal with `talos chat` |
| Identical input and state, byte-identical output | yes: the golden suite run twice and in reverse order |
| `talos explain` shows every stage | yes, including safety and reflector |
| Memory at rest ≤ 8 MB | 6.8 MB for a one-shot question; **8.2–8.4 MB peak** for a process that has served rule and reflector turns in both languages (peak footprint 6.7–6.9 MB). At the line, not under it |
| Rule-matched turn p99 ≤ 2 ms | 15 µs; a reflector turn 0.66 ms |
| Binary ≤ 6 MB | 1.4 MB |

Open:

- E2 baseline recorded in `evals/BASELINE.md`: with rules only, 49.5 %
  (Spanish) and 48.0 % (English) on the intents of the seven built skills,
  and no false accept on the rejection sets.
- **E4 not done.** `cargo deny` is not installed on the development machine,
  so `deny.toml` remains unvalidated (as in M0). The binary's dependency tree
  is 26 crates, all from the `regex`, `serde`, `toml` and
  `unicode-normalization` families.
- **Stand-alone battery baseline** (not a gate), measured before the last
  pattern fix: bare catch-all on 37.9 % of turns in both languages; on turns
  meant for the reflector, 50 % in Spanish and 39 % in English; one false
  deflection in English.
- Messages with no word that marks a language ("bye", "d20") are taken as the
  default language until the classifier of v0.2.
- Without a place, the distress reply names no emergency number; whether a
  configured default region should apply is undecided.
- `calc.arithmetic` has priority 40, below every other intent: its patterns
  are broad and its handler declines what is not an expression.
- The CLI still reads the UTC offset by running `date +%z` each turn.

## When can we say "hola"?

At the end of **Slice A** — ten small tasks, the first deliverable of the
milestone, roughly a sixth of v0.1 by task count.

It depends on nothing still open: the scaffold builds, `smalltalk.greet` is
specified, and the slice touches only `crates/` and `skills/`. It does not
need the classifier, the knowledge store, the reflector or the server.

Estimate, not a commitment: Slice A is on the order of 700–1,000 lines of Rust
with tests, small enough to be written by one implementer in a single working
session and reviewed in the same one. Slices B–E are several sessions more;
C and D run in parallel once B lands.

## Decisions to take as work starts

Small enough not to need a record each unless they turn contentious; to be
noted in [DEVELOPMENT.md](../DEVELOPMENT.md) when taken.

| Question | Leaning | Why |
|---|---|---|
| Argument parsing | hand-written or a micro-crate for now | three subcommands do not justify a large CLI framework yet |
| Pattern engine | `regex` with `RegexSet` | linear time, no backtracking; no look-around, which keeps patterns simple |
| Unicode normalisation | `unicode-normalization` | small, standard |
| Dates and time zones | one crate providing civil time and the zone database | decide by binary size measured in Slice C |
| Manifest embedding | `include_str!` of files listed by a build script | no run-time file access for built-ins |
| Random source | a small generator implemented in-tree behind a trait | determinism, no dependency |
| Arithmetic | exact decimals/rationals in-tree | correctness of `0.1 + 0.2`; floats only for roots and the like |
| Golden file format | plain text mirroring the spec's exchange format | spec examples transcribe mechanically |

## Who does what

Slices are sized for delegation.

| Work | Suited to | Why |
|---|---|---|
| Slice A and B | the most capable model, one implementer | sets the engine's public shape; everything else builds on it |
| C2, C3, C6, C7 and C1 | a mid-tier model, one per skill | scoped, specified, test-backed |
| C4, C5 | a mid-tier model, reviewed closely | dates and arithmetic are where subtle errors hide |
| D2, D3, D5 | the most capable model | Spanish reflection is linguistically delicate |
| Transcribing spec examples into golden files | the smallest model | mechanical |
| E3 measurements | the smallest model | run and report |

## Risks specific to this milestone

| Risk | Mitigation |
|---|---|
| The engine's shape is fixed too early by Slice A | Slice A stays thin; B is allowed to reshape it before any skill depends on it |
| Rules-only recognition feels brittle and tempts pattern sprawl | accept it: paraphrase is v0.2's job; keep patterns to the obvious phrasings |
| Skills needing a missing slot have no way to ask | usage hint and `unhandled` in v0.1; open questions arrive in v0.2 |
| Spec examples disagree with each other | the cross-review in M0 precedes Slice C; conflicts found later change the spec first |
| Spanish reflection produces broken grammar | the guard list and the forbidden-reply test in D3 and D6 |
