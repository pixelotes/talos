# M2 — v0.2 "Understands paraphrase": implementation plan

The working plan for the milestone in [ROADMAP.md](../ROADMAP.md). It starts
from the rules-only baseline in [evals/BASELINE.md](../../evals/BASELINE.md):
about half of the held-out phrasings of a built skill are recognised, and
nothing is accepted wrongly.

Implementation works from [docs/spec/](../spec/README.md), chiefly
`conversation.md` (slots, open questions, commands) and `state.md`
(`timezones`, `preferences`).

## Slices

```
A  classifier ───────────────────────┐
                                     ├─▶ C  skills and corrections ─▶ D  measure and close
B  commands, slots, open questions ──┘
```

A and B run in parallel; they meet only in the pipeline, at different stages.

### Slice A — the classifier

| # | Task |
|---|---|
| A1 | Model file format: versioned, vocabulary table, pruned and quantised weights, corpus hash |
| A2 | Offline trainer, one command, from manifest examples; an out-of-scope class |
| A3 | Inference in Rust: character n-gram TF-IDF, sparse dot product; no ML dependency at run time |
| A4 | Pipeline stage after rules: absolute threshold and margin; the trace records the candidates |
| A5 | Language detection step 3 ([ADR 0015](../adr/0015-language-detection.md)) |
| A6 | Training examples: enough native phrasings per intent and language in the manifests |
| A7 | `talos eval` reports accuracy, false-accept rate and catch-all rate, with and without the classifier |

**Held-out rule.** Training examples are written without opening the
batteries in `evals/`. Only aggregate figures from `talos eval` guide the
work. Thresholds may be tuned against the batteries
([ADR 0008](../adr/0008-intent-classification.md)).

**Done when** `talos eval` reports the targets or the measured gap to them,
the model is under 2 MB, and a stale model is refused.

### Slice B — commands, slots, open questions

| # | Task |
|---|---|
| B1 | Command shortcuts in the manifest, the rule stage, the validator and `/help` ([ADR 0016](../adr/0016-command-shortcuts.md)) |
| B2 | Slot types: `duration`, `datetime`, `place`, `language`, `choice`, `confirm`, in both languages |
| B3 | `Ask`: expectations with expiry, cancellation, release on an unrelated message, asking again |
| B4 | Golden format for multi-turn exchanges with an open question |
| B5 | The built skills ask instead of giving a usage hint where the specification says so; each gets its commands |

**Done when** a slot-filling exchange and its cancellation pass as golden
transcripts in both languages, and `/calc 1 + 2` answers as the sentence does.

### Slice C — skills and corrections (after A and B)

| # | Task |
|---|---|
| C1 | `timezones`: `time_in`, `difference`; the zone data source decided by measured size |
| C2 | `preferences`: `set`, `get`, `forget`; where they are stored |
| C3 | User-correction table, consulted at the rule stage |
| C4 | Classifier examples for the new skills; retrain |

### Slice D — measure and close

| # | Task |
|---|---|
| D1 | Accuracy, false accepts, model size, classifier stage p99, memory; recorded |
| D2 | Floors in CI per language |
| D3 | The battery rows identical to a specification example tagged, and accuracy reported with and without them (M0 follow-up) |
| D4 | The server's open-question exit criterion of v0.4, now testable |

## Exit criteria

The roadmap's: intent accuracy English ≥ 95 %, Spanish ≥ 92 %, gap ≤ 4
points; false accepts ≤ 3 %; model ≤ 2 MB; classifier stage p99 ≤ 1 ms; a
slot-filling exchange and its cancellation as golden transcripts in both
languages. All are targets to be confirmed or revised by measurement.

## Status (2026-11-25): closed, with the accuracy targets not met

Slices A to D are merged; 311 tests pass and `talos skills check` is clean
with nine skills.

| Exit criterion | Result |
|---|---|
| Intent accuracy: English ≥ 95 %, Spanish ≥ 92 %, gap ≤ 4 points | **not met**: 87.2 % and 88.4 % on built skills (84.5 % and 86.3 % on rows not in the specification); gap 1.2 points |
| False accepts ≤ 3 % | Spanish 4.0 % (**one row over**), English 2.0 % |
| Model ≤ 2 MB; classifier stage p99 ≤ 1 ms | 0.68 MB; 32 µs (the implementer's figure, not repeated) |
| A slot-filling exchange and its cancellation as golden transcripts, both languages | yes (`golden/engine/questions.txt`) |

Details and the threshold sweep are in `evals/BASELINE.md`. The owner
decides whether the targets are revised or pursued further; the floors in
`crates/talos/tests/eval.rs` keep what has been reached.

Done in Slice D: more examples and rules for the weak intents; `/calc`
reaches percentages and conversions; `preferences` checks a place against
the place table shared with `timezones` and asks which one when a name is
ambiguous; battery rows that also appear in the specification are tagged and
reported apart; floors on every test run; patterns are compiled only when a
text could match them.

Open:

- The accuracy gap. Working blind from aggregate figures added about one
  point; the remaining misses are mostly "no intent", spread over many
  intents (help.skill, preferences, timezones.difference, fortune).
- Resident memory of a chat is 9.0–9.7 MB, above the 8 MB target of v0.1; a
  one-shot question is 7.5–8.1 MB.
- The correction table has no spoken way in until `teach.phrase` (v0.3).
- The zone rules are verified from 2027-03-14 to 2036. Before that date a few
  zones whose rules changed recently (Cuba, Morocco, British Columbia,
  Alberta) can be wrong.
- An answer that carries a second request is not split; "allí" after a named
  place is not tracked.
- `a_slow_client_does_not_block_others` (server) asserts a 250 ms bound and
  fails when the machine is heavily loaded.
